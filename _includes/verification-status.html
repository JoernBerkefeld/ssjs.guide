{% comment %} Renders a single page-level verification-status badge. Status values (front matter `verification:`): verified - every method/constructor/property on the page is runtime-verified (green) in-progress - some but not all are verified (yellow) pending - none verified yet, or field absent (grey; default) The page's own `verification:` front matter is the source of truth for BOTH leaf pages and overview (index) pages. Overview pages are cross-listed in _data/navigation.yml (a page can appear under several sections — e.g. HTTP.Get is listed under both /http/ and /core-library/), so a URL-prefix scan cannot reliably find an overview's children. The verify-ssjs-guide-docs skill computes and writes each overview's `verification:` (and `differs_from_docs:`) explicitly from navigation.yml membership. Only when an overview page has NO explicit `verification:` field do we fall back to aggregating URL-prefix children (legacy behaviour), skipping jekyll-redirect-from stubs (which carry a `redirect` object and no `verification` field). {% endcomment %} {% assign status = "pending" %} {% assign differs = false %} {% if page.verification %} {% comment %} Explicit front matter wins for leaf and overview pages alike. {% endcomment %} {% assign status = page.verification %} {% if page.differs_from_docs %} {% assign differs = true %} {% endif %} {% else %} {% comment %} No explicit status: fall back to URL-prefix child aggregation.
